# Apple Health (HealthKit) — проверка на реальном iPhone

HealthKit нельзя полноценно проверить в браузере или симуляторе без данных. Этот список — ручная приёмка
на физическом iPhone.

## Что было причиной «Error»

1. **Expo Go.** В Expo Go нет нативного модуля `@kingstinct/react-native-healthkit` (Nitro). Раньше приложение
   всё равно пыталось загрузить модуль, и в dev-режиме это давало красную ошибку и неясное состояние.
   Теперь Expo Go определяется через `Constants.executionEnvironment === 'storeClient'` *до* загрузки модуля,
   и экран показывает «HealthKit недоступен — нужна сборка RYNJI».
2. **Сборка без модуля.** Если development build собран *до* добавления библиотеки/плагина, модуля в бинарнике нет.
   Состояние: «HealthKit недоступен — модуль не найден, нужна новая нативная сборка», техническая причина — в «Подробнее».
3. **Ошибки проглатывались.** `requestAuthorization` ловил исключение и возвращал `false` → пользователь видел
   «доступ не выдан» вместо реальной ошибки. Теперь текст ошибки сохраняется, логируется (`console.warn`) и
   показывается в «Подробнее» с кнопкой «Повторить».
4. **Лишнее разрешение.** Запрашивалась дистанция ходьбы/бега, которая не используется в решениях. Убрано.

Возможная причина, которую можно подтвердить только на устройстве: библиотека 16.0.0 сгенерирована nitrogen 0.35,
в проекте `react-native-nitro-modules` 0.37.1 (peer-зависимость библиотеки `>=0.35` — формально совместимо).
Если на устройстве в «Подробнее» будет ошибка про Nitro/HybridObject — зафиксировать версию Nitro по README библиотеки.

## Нужна новая нативная сборка

Да, если текущая dev-сборка сделана до добавления HealthKit или до изменений `app.json`:

```bash
npx eas-cli@latest build --profile development --platform ios
```

`ios/` не редактируется вручную (CNG): entitlement `com.apple.developer.healthkit` и `NSHealthShareUsageDescription`
добавляет config plugin `@kingstinct/react-native-healthkit` из `app.json`. Запись в Health не запрашивается
(`NSHealthUpdateUsageDescription: false`).

## Чек-лист приёмки

Подготовка: iPhone с данными в «Здоровье» (шаги, сон, лучше — Apple Watch для HRV и пульса покоя).

- [ ] Установлена **новая** development build (не Expo Go).
- [ ] Профиль → Apple Health: статус «Не подключено», кнопка «Подключить Apple Health».
- [ ] Нажать «Подключить»: появляется системный лист iOS ровно с 7 категориями: Сон, Шаги, Масса тела,
      Пульс в покое, Вариабельность пульса, Активная энергия, Тренировки. Ничего на запись.
- [ ] Разрешить всё → статус «Подключено», «Последняя синхронизация: сегодня в ЧЧ:ММ».
- [ ] Показатели (сон, шаги, пульс покоя, HRV) совпадают с приложением «Здоровье» за сегодня (сон — за прошлую ночь).
- [ ] Чек-ин: время сна подставлено из Health, подпись «Источник: Apple Health · можно изменить».
- [ ] Изменить сон колесом (например, 7 ч 43 мин) → сохранить → снова открыть чек-ин: значение ручное, не перезаписано Health.
- [ ] Главная: «Шаги» показывает «текущие / цель», цель объяснена в листе «Шаги».
- [ ] В «Здоровье» → профиль → Приложения → RYNJI выключить все категории → «Синхронизировать»:
      статус «Нет разрешения» с подсказкой, где включить (iOS не сообщает об отказе напрямую).
- [ ] Включить обратно → «Повторить» → снова «Подключено».
- [ ] Режим полёта/без данных: приложение не падает, ручной чек-ин работает.
- [ ] Открыть ту же сборку в Expo Go (если применимо): статус «HealthKit недоступен (Expo Go)», без красного экрана.
- [ ] iPad (если есть): «HealthKit недоступен на этом устройстве».
- [ ] При любой ошибке: «Ошибка подключения» → «Подробнее» показывает технический текст, в логах Xcode/Metro —
      строка `[RYNJI] HealthKit <место>: <ошибка>`.

## Где в коде

- `src/services/health/index.ts` — загрузка модуля, определение Expo Go, разрешения, чтение данных, логирование.
- `src/features/health/state.ts` — состояние для UI (чистая функция, покрыта тестами).
- `src/features/health/sync.ts` — подключение и синхронизация, сохранение ошибки.
- `src/app/health.tsx` — экран со статусами «Подключено / Нет разрешения / Недоступен / Ошибка».
