# RYNJI 2.0 — фаза C: питание

Все снимки — **web-рендер** 393×852 в Linux Chromium (Inter вместо SF Pro). На iPhone не проверено на устройстве. Поиск в Open Food Facts в веб-превью блокирует CORS — это ограничение превью; на iPhone поиск по сети тоже не проверен.

## Что сделано

| Шаг | Что изменилось |
|---|---|
| C1. Схема v2 | Единицы порций (г, мл, шт, порция, упаковка), статус данных продукта и атрибуция, рецепты, корзина. Хранилище `form.nutrition` — тот же ключ, версия 1 → 2: записи дневника переносятся байт в байт, продукты получают статус и единицу «порция», битые записи отбрасываются. Резервные копии восстанавливаются той же миграцией и теперь содержат рецепты. КБЖУ в записи — неокруглённый снимок, округляется только итог: ошибка не растёт с числом записей |
| C2. Поиск | Один сервис для всех источников: нормализация («5 %» = «5%», ё, латиница брендов), синонимы («гречка» ↔ «гречневая крупа»; «рыба» → лосось, но «лосось» ≠ треска), опечатки («тварог» → творог) — по своим и базовым продуктам; единое ранжирование; склейка дублей по штрихкоду; новый запрос отменяет старый. Свои и базовые продукты — сразу, Open Food Facts и USDA — по мере ответа |
| C3. Дневник | Неделя дней (сегодня справа, точка — есть записи, свайп — прошлые недели), «осталось / съедено / цель» на шкале, Б/Ж/У и клетчатка шкалами, приёмы пищи одной группой, строка продукта показывает, как ввели («2 шт, 80 г»). Удаление свайпом, копирование дня или приёма, «обычный» приём — с «Отменить» 8 секунд. Правка порции — тоже с «Отменить» |
| C4. Добавление | «+» у приёма сразу открывает добавление в этот приём и день. Недавние · Избранное · Мои, поиск, штрихкод, свой продукт (с весом 1 шт). Тап — лист порции (приём, количество в г / шт / порциях, КБЖУ на 100 г и на порцию). «+» в строке — сразу в корзину с привычной порцией; корзина добавляет всё одним действием и переживает закрытие приложения. Промежуточный лист «Добавить в…» убран |
| C5. Рецепты | Ингредиенты, вес готового блюда (с проверкой), порции; КБЖУ на 100 г готового и на порцию пересчитываются на каждое изменение. Рецепт — в «Моих», добавляется граммами или порциями. Правка рецепта не меняет прошлые записи |
| C6. Аналитика | «Прогресс» → «Питание» за 7 / 30 / 90 дней: средние по учтённым дням (2 приёма или 800 ккал; сегодня не входит), сколько дней учтено, % от цели, калории по дням с линией цели, связь с весом — только при 14 учтённых днях и 4 взвешиваниях, иначе — чего не хватает |
| C7. FatSecret | Не делалось: нужно решение владельца (тариф, договор, сервер). Поиск устроен так, что провайдер добавляется одной строкой на сервере |

## Критерии NUTRITION_SPEC.md §1

| Критерий | Как проверено |
|---|---|
| Повторный продукт ≤ 3 действий | e2e 60: «+» у обеда → продукт в «Недавних» → «Добавить в обед», порция прошлого раза |
| Поиск не блокирует ввод | свои и базовые — синхронно на каждый символ, сеть — после паузы и отменяется новым вводом (unit-тест отмены) |
| Граммы мгновенно пересчитывают КБЖУ | лист порции и рецепт считают на каждое изменение; e2e 63, 64 |
| Любое действие обратимо | удаление, копирование, корзина, правка порции — «Отменить» (e2e 59, 61, 63) |
| Сохранение не стирает историю | снимки КБЖУ: unit-тесты и e2e 64 (правка рецепта не меняет запись) |
| Офлайн | e2e 62: сеть отключена, поиск с опечаткой и добавление работают |
