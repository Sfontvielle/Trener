# Анатомические 3D-модели RYNJI — архитектура (этап 1)

Замена процедурной фигуры `tools/anim` на анатомические модели (мужская и женская) для роликов техники.
Модель-источник и лицензии — `docs/anatomy-3d/ASSET_OPTIONS.md`. **Пока модель не получена, эта папка содержит только
спецификации и договорённости; ни одного кадра «из примитивов» как замены анатомии здесь нет.**

## Слои

```
персонажи (приватно)        тренажёры (в репозитории)       упражнение (в репозитории)
male.blend / female.blend   equipment.blend                 exercises/<id>.json
  риг: IK/FK, кисти, стопы    оси вращения рычагов,           фазы и углы суставов, хват,
  мышцы — отдельные объекты   ручки, блоки, тросы,            тренажёр, камеры, подсветка
  с каноническими id          скамьи, грифы, гантели          по каноническим id
          \_______________________  ____________________________/
                                  \/
                    render.py (headless Blender, Cycles)
                    сцена = персонаж + тренажёр + действие + подсветка
                                  │
                    кадры PNG → tools/anim/encode.py (WebP-петля + постер)
                                  │
              assets/anim/<id>.webp, <id>_f.webp (+ posters) → tools/anim/registry.ts
                                  │
              src/data/exerciseAnimations.ts (loop / loopF) → ExerciseAnimation по полу из профиля
```

- **Персонажи** не хранятся в публичном репозитории (лицензия). Путь задаётся переменной `ANATOMY_BLEND_DIR`
  (приватный репозиторий с Git LFS или папка с Mac через Remote Control).
- **Имена мышц**: канонические id из `src/features/exercises/anatomy/muscleIds.ts`, сторона — `.L` / `.R`
  (`deltoid_anterior.L`). Если в модели объекты названы иначе — `asset_map.json` (имя объекта в .blend → id).
  `npx tsx tools/anatomy3d/export-muscles.ts` пишет `muscles.json` для скриптов Blender.
  Одни и те же id — у мужской и женской модели, у 2D-карты и у подсветки упражнений.
- **Подсветка** — по объектам мышц, поэтому движется вместе с деформацией. Один материал на все мышцы с атрибутом
  роли (0 — не работает, 1 — слегка, 2 — основная). Шейдер смешивает базовый серо-белый цвет с цветом роли
  и добавляет мягкое свечение по краям (Fresnel), а не заливает руку или спину целиком.
  Интенсивность — визуальная подсказка, а не измерение активации.
- **Палитра** — параметр рендера: `reference` (основные — красно-оранжевые, вспомогательные — светло-оранжевые,
  остальное — серо-белое, белый фон, как на референсах) или `app` (зелёный и светло-жёлтый, как карта мышц).
  Выбор — за владельцем (`ASSET_OPTIONS.md`, раздел 5).
- **Тренажёр** движется вместе с телом: рычаг вращается вокруг своей оси, кисть привязана к рукояти
  (IK-цель кисти — объект хвата на рукояти), стопы — к платформе, таз — к сиденью. Пересечения проверяются
  по кадрам (раздел «Проверка»).
- **Цикл** без рывка: позы фаз — ключи в одном действии; `t=0` и `t=1` — одна поза; интерполяция
  ease-in-out; пауза в пиковом сокращении — по спецификации упражнения.

## Почему офлайн-рендер, а не 3D-движок в приложении

Предрендеренный WebP (как сейчас) — ~0,1–0,3 МБ на ролик, работает офлайн и на любом iPhone без нагрузки на GPU.
Интерактивный GLB/USDZ-просмотр остаётся возможным: модели и действия уже в Blender, экспорт — отдельный шаг.
Но только при письменном разрешении автора на встраивание геометрии в приложение и после проверки
производительности на iPhone.

## Рендер

- Проверено 6.11.2026: `pip install bpy` → Blender 5.0.1 headless, Cycles на CPU работает (простая сцена 960×720 —
  ~10 с/кадр на 4 ядрах). EEVEE без GPU недоступен.
- Демо (2 упражнения × 2 фигуры × ~70 кадров) реально отрендерить здесь; всю библиотеку — на машине с GPU.

## Проверка каждого ролика (до коммита)

1. Кадры начала, середины и конца — минимум с двух ракурсов из спецификации.
2. Нет пересечений тела с тренажёром и тела с самим собой; хват на рукояти; стопы и таз на опорах.
3. Амплитуда и траектория — по спецификации (углы суставов в ключевых фазах).
4. Шов цикла: разница первого и последнего кадра не больше, чем между соседними кадрами.
5. Сравнение со стилем референсов: рельеф, разделение мышц, точечная подсветка, никаких «пузырей».
6. Заметка о проверке — в `tools/anim/manifest.json` (`checked: true` только после просмотра).

## Демонстрационный этап

`exercises/machine_row.json`, `exercises/pec_deck.json` — биомеханика, фазы, тренажёр, камеры и подсветка
по каноническим id. На всю библиотеку не расширяем, пока владелец не подтвердит качество персонажей,
деформацию и систему анимации.
