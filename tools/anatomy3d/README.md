# Анатомические 3D-модели RYNJI — архитектура

Собственные анатомические модели (мужская и женская) для роликов техники, собранные из открытого атласа
**Z-Anatomy / BodyParts3D** (CC BY-SA). Ничего не покупается. Лицензии и атрибуция — `docs/ASSETS_LICENSES.md`.
Сценарии сборки, рига и рендера — `blender/` (см. `blender/README.md`).

## Слои

```
атлас Z-Anatomy (≈7 200 объектов, CC BY-SA)
  │ build_male.py      — отбор: ~210 мышц (головки отдельно), сухожилия, ~210 костей, кожа головы/кистей/стоп, глаза
  │ physique.py        — телосложение: прирост каждой мышцы по брюшку, послойно (мужчина — бодибилдер, женщина — спортсменка)
  │ morph_female.py    — женские пропорции скелета и мышц вместе (крепления остаются на костях)
  │ female_extras.py   — грудь, волосы-скульптура с пучком
  │ garment.py         — одежда по выпуклой оболочке тела: плавки / спортивный топ с лямками и трусы
  ▼
male.blend, female.blend (вне репозитория, воспроизводятся сценариями)
  │ rig.py             — арматура по суставам скелета (43 кости: туловище, плечевой пояс, рука, кисть, 14 фаланг, нога);
  │                      кости скелета — жёстко, мышцы/кожа/одежда — веса по близости к костям своего участка тела
  ▼
male_rig.blend, female_rig.blend
  │ anim.py + exercises/<id>.json + atlas_map.json
  │                    — позы по фазам и суставным углам, тренажёр, кисть на рукояти (ИК), свет, камера, подсветка
  ▼
кадры PNG → onwhite.py (белый фон, мягкое свечение подсветки) → WebP-петля + постер
  ▼
assets/anim/<id>.webp, <id>_f.webp → tools/anim/registry.ts → src/data/exerciseAnimations.ts
  ▼
ExerciseAnimation выбирает ролик по полу из профиля (sex → loop / loopF)
```

## Что переиспользуется на всю библиотеку

- **Модели и риг** — одни на все упражнения. Новое упражнение = новый `exercises/<id>.json` (фазы, суставные углы, хват,
  тренажёр, камера, подсветка). Позы задаются углами (`posing.py`): сгибание/отведение плеча, горизонтальное сгибание,
  локоть, лопатка (ретракция, подъём), наклон корпуса, таз/колени; кисть может держать рукоять через ИК.
- **Подсветка** — по каноническим id приложения (`src/features/exercises/anatomy/muscleIds.ts`) через одну таблицу
  `atlas_map.json` (id → объекты атласа). Та же разметка упражнения, что и у 2D-карты мышц.
- **Тренажёры** — процедурные (`anim.py`): рычаги вращаются вокруг своих осей, рукоять идёт по дуге, кисть — на рукояти
  (ошибка хвата печатается при рендере; в демо — 0 мм). Для следующих упражнений — те же функции (трубы, пады, диски).
- **Палитра** — `stage.highlight`: основные — насыщенный красно-оранжевый, вспомогательные — светло-оранжевый, остальное —
  серо-белое (как на референсах). Зелёно-жёлтая палитра 2D-карты — тот же вызов с другими цветами.

## Почему офлайн-рендер, а не 3D-движок в приложении

Предрендеренный WebP — сотни килобайт на ролик, работает офлайн и на любом iPhone без нагрузки на GPU. Модели в `.blend`
с ригом остаются источником: экспорт в GLB/USDZ для интерактивного просмотра — отдельный шаг (лицензия CC BY-SA это
допускает с атрибуцией), но сначала — проверка производительности на iPhone.

## Рендер

- `pip install bpy scipy` → Blender 5.0.1 headless, Cycles на CPU. Модель — ~1,75 млн треугольников; кадр 640×480,
  16 сэмплов + шумоподавление — десятки секунд на 4 ядрах. 4 демо-ролика — часы здесь; всю библиотеку — на машине с GPU.

## Проверка каждого ролика (до коммита)

1. Кадры начала, пика и возврата — минимум с одного ракурса из спецификации, для пиков — крупно.
2. Хват на рукояти (ошибка ИК), таз на сиденье, стопы на платформе; нет пересечений тела с тренажёром.
3. Амплитуда и траектория — по спецификации (углы в ключевых фазах).
4. Шов цикла: первый и последний кадр — одна поза (кадр N совпадает с кадром 0 и не рендерится).
5. Сравнение со стилем референсов: рельеф, разделение мышц, точечная подсветка.

## Демонстрационный этап

`exercises/machine_row.json`, `exercises/pec_deck.json` — по 2 ролика (мужчина/женщина). На всю библиотеку не расширяем,
пока владелец не подтвердит качество моделей, деформацию и систему анимации.
